# AGENTS.md — правила проєкту KBase-m_dev

> Обов'язково для всіх ШІ-агентів (OpenCode, Antigravity, Cursor, Copilot, Codex, Claude тощо)
> та для всіх учасників проєкту.

## 1. Відступи: ТІЛЬКИ таби (TABS), НЕ пробіли

- Весь новий код і всі зміни існуючого коду — **завжди з відступами табами (`\t`)**.
- **Заборонено** використовувати пробіли для відступів (indentation), в тому числі:
  - початок рядка,
  - вкладені блоки `if / for / while / try / class / method`,
  - продовження рядків (line continuation),
  - вирівнювання в XML / FXML / properties / SQL / shell.
- Один рівень вкладеності = **один таб** (`\t`).
- Не змішувати таби і пробіли в одному файлі для відступів. Якщо редагуєш старий фрагмент з пробілами — переведи цей фрагмент на таби.
- Ширина відображення таба: **4** (тільки для перегляду, в файлі зберігати саме `\t`, а не 4 пробіли).
- Вирівнювання всередині рядка (наприклад, після коду) — теж табом, а не пробілами, де це можливо.

Це стосується ВСІХ файлів: `*.java`, `*.xml`, `*.fxml`, `*.properties`, `*.sql`, `*.sh`, `*.bat`, `*.js`, `*.ts`, `*.json`, `*.md` (блоки коду) тощо.

### Винятки (єдині, де пробіли дозволені)

- Вирівнювання всередині багаторядкових коментарів `*`, де таб зламає візуальне вирівнювання — залишати як є, але відступ самого коментаря все одно табом.
- String-літерали, де пробіли є частиною значення — не чіпати.

## 2. Машинна перевірка

- Еталон — `.editorconfig` в корені проєкту (`indent_style = tab`).
- Налаштування IDE — `.vscode/settings.json` (`editor.insertSpaces: false`, `editor.detectIndentation: false`).
- Перед завершенням завдання перевір: `grep -rn "^ " --include="*.java" <змінені файли>` не повинен знаходити відступи пробілами в новому коді.

## 3. Пріоритет

Це правило має вищий пріоритет за дефолтні звички форматера / IDE.
Якщо форматер пропонує пробіли — переналаштуй його на таби, не навпаки.
